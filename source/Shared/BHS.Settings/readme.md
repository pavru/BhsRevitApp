# BHS.Settings

Слоистые настройки с диска. Обе стороны — Revit-side и Win-side — читают их независимо и
стартуют **без канала**; по каналу потом едет только то, что знает одна сторона.

## Что читается и в каком порядке

Три каталога, в каждом до трёх файлов. Позже прочитанное побеждает.

| Слой | Каталог |
|---|---|
| `Product` | рядом со сборкой; для add-in это его `Lib` |
| `Machine` | `%ProgramData%\BHS` |
| `User` | `%AppData%\BHS` |
| `Process` | переменные `BHS_*` |

Имена: `appsettings.json` → `appsettings.<сторона>.json` → `appsettings.revit<год>.json`.
Сторона — `revit` или `winside`; файл по году читает только Revit-side.

`BHS_LAUNCH__SHUTDOWNTIMEOUT` → ключ `Launch:ShutdownTimeout`: двойное подчёркивание вместо
двоеточия, которого в имени переменной быть не может.

```csharp
using var settings = LayeredSettings.Read(new SettingsOptions
{
    Side = ProcessSide.Revit,
    Release = 2026,
});

var shutdown = settings.Section("Launch").Duration("ShutdownTimeout", TimeSpan.FromSeconds(240));
settings.Changed += (_, _) => { /* файл поменялся */ };
```

## Почему здесь нет ни одной ссылки на пакет

Это половина, которая едет внутрь Revit, а там всякая наша сборка — сборка, которую может
привезти и кто-то ещё.

Измерено на Revit 2026: первая версия читала настройки через `Microsoft.Extensions.Configuration`
10.0 и **не загрузилась вовсе** — `DynamoForRevit` из каталога самого Revit везёт
`Microsoft.Extensions.Configuration.Abstractions` **2.0.0.0**, занимает простое имя раньше любого
add-in, и запрос более высокой версии кончается `FileLoadException`. На той машине для 2026
установлено 23 копии этой сборки.

`Microsoft.Extensions.Configuration.Json` вдобавок стоил бы на `net48` 17 сборок против 3, из них
9 полифиллов BCL, включая `System.Text.Json`, — а его Revit не возит вовсе, то есть версию не
закрепляет никто. Отсюда свой читатель JSON в `JsonSettings.cs`.

Кому нужен `IConfiguration` поверх этих файлов — берёт `BHS.Settings.Configuration`. Это Win-side.

## Формат

JSON с послаблениями, которые делает и штатный провайдер: комментарии `//` и `/* */`, висячая
запятая. Вложенность склеивается двоеточием, массивы индексируются по порядку, числа и
`true`/`false` сохраняют написание.

Явный `null` и пустой объект **сохраняются как значение** — так глубокий слой снимает то, что
задал мелкий. Ключ, заданный дважды в одном файле, — ошибка; между файлами — ровно то, ради чего
слои и нужны.

Значение, которое есть и не читается (`"soonish"` там, где ждут длительность), **отвергается**,
а не подменяется умолчанием.

## Перезагрузка

Каждый файл под наблюдением, с задержкой 250 мс: редакторы пишут файл не один раз.

Слой, чьего каталога ещё нет, не наблюдается — навести `FileSystemWatcher` на отсутствующий
каталог нельзя, а создавать пустые папки в `%ProgramData%` на каждом старте мы не будем. Такой
слой подхватится на следующем запуске.

Ошибка чтения при перезагрузке **записывается** (`LayeredSettings.Errors`), а не бросается: бросок
пришёл бы с потока таймера, где ловить некому, и внутри Revit это чужая сессия. Первое чтение —
другое дело, там вызывающий есть.
